File Processing Playground

Sends a file to POST /file-processing/process — ported from ai-platform's file-type router: PDF pages use their own text layer, and only get rendered + sent to Omni when that layer is (near) empty or a single embedded image dominates the page. DOCX/PPTX/XLSX use native readers for text and send only embedded images worth analyzing to Omni. Images/audio/video go to Omni whole. The key number below is units using Omni out of total units — how much of the file actually needed vision, not the page count. Omni OCR is the sum of every Omni call's own latency. A PDF's qualifying pages all OCR concurrently, and multiple images on one slide/sheet do too, so the sum overstates the wait there — but DOCX/PPTX/XLSX still walk their slides/sheets one at a time (matching ai-platform's own structure), so across those the sum is close to the actual wait; the slowest single call (also shown) is the floor either way.
